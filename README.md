# Staff Pulse Dashboard

Интерактивный dashboard структуры организации. Локально реализованы все четыре этапа: дерево и аналитика, realtime-патчи SSE, production-обвязка и AI-поиск с детерминированной server-side заглушкой.

## Запуск

```bash
npm install && npm run dev
```

Откройте `http://localhost:5173`. API доступен по `http://localhost:3001/api/org-tree`.

Полезные команды: `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`.

`MOCK_DELAY_MS` (по умолчанию 400) управляет задержкой mock API; пример переменных — [.env.example](.env.example).

## Реализованное на первом этапе

- React, TypeScript strict и Vite; Express запускается одной командой с frontend.
- `GET /api/org-tree` возвращает плоский массив из 52 записей и revision header.
- TanStack Query использует `AbortSignal`, cache key `['org-tree']`, `staleTime: 5000`, одну повторную попытку и не refetch-ит на focus.
- Внешний ответ проверяется Zod, далее проверяются duplicate ID, orphan, self-parent, cycle и unreachable nodes.
- UI показывает loading, error с retry и empty states. Корневые узлы открыты — второй уровень сразу виден; вся информационная часть строки дерева — доступная кнопка выбора, а раскрытие остаётся отдельной кнопкой с `aria-expanded`.

## Реализованное на втором этапе

- Для каждого подразделения один post-order обход вычисляет суммарную численность, бюджет и взвешенную по численности эффективность; при нулевой численности эффективность — `—`.
- Таблица сортирует все столбцы стабильно, отображает `aria-sort`, форматирует бюджет и эффективность для русской локали и сохраняет `null` эффективности в конце выдачи.
- Поиск по названию нормализует пробелы и регистр, применяется через 250 мс, имеет очистку и состояние «не найдены».
- Выбор общий для дерева и таблицы; при выборе строки раскрывается путь к соответствующему узлу. На ширине от 1280 px оба представления видны одновременно, ниже доступны вкладки.

## Реализованное на третьем этапе

- `GET /api/org-tree/events?since=<revision>` передаёт SSE-патчи, heartbeat и `sync-required`; сервер хранит последние 100 патчей и симулирует изменение метрики через `LIVE_UPDATE_MS` (по умолчанию 5000 мс).
- Клиент применяет последовательный patch к query cache без полного refetch, пересчитывая только изменённый узел и его предков. Gap, невалидный patch или `sync-required` запускают controlled refetch.
- В шапке показано состояние подключения, изменённые значения подсвечиваются 1,5 секунды, строки таблицы поддерживают roving tabindex, а дерево анимирует раскрытие с уважением `prefers-reduced-motion`.

## Production и Docker

AI-поиск работает через полноценный внутренний контракт фильтра: уровни, численность, бюджет, эффективность и сортировка применяются на клиенте. Сейчас server interpreter — детерминированная заглушка без ключа и внешних вызовов; она понимает базовые запросы вроде «уровень 2», «от 20 человек» и «сортируй по бюджету по убыванию». Граница `SearchInterpreter` подготовлена для подключения Responses API позднее; ключ должен оставаться только в server environment, а не во frontend.

Запуск production-стека одной командой:

```bash
cp .env.example .env && docker compose up --build
```

Откройте `http://localhost:8080`. Файл `.env` не хранится в Git: он передаётся только server-контейнеру. В текущем demo-режиме `OPENAI_API_KEY` не нужен; `OPENAI_MODEL` зарезервирован для будущего server-only адаптера.

## Использование AI

AI-ассистент Codex сгенерировал первоначальные заготовки Vite/React/Express, fixture организации, Zod-контракт, графовую нормализацию, базовые компоненты дерева и черновики документации.

Вручную доработаны: разделение слоёв (запрос и построение графа находятся в `entities/org-node/api`, а не в `shared`), обработка невалидного JSON, тестовые сценарии графа и HTTP-контракта, а также семантика и focus-state строки дерева. Эти правки внесены, чтобы зависимость `shared → entities` отсутствовала, ошибки внешнего API были понятны, а управление деревом соответствовало клавиатурной доступности.

Дополнительно вручную реализованы SSE-replay и controlled recovery, инкрементальная агрегация, production-конфигурация Docker/Nginx, AI-контракт и fallback. Генерируемые заготовки были проверены и переработаны, потому что для патчей важны порядок revision, неизменяемость query cache, а секреты не должны попасть в frontend image.

Технический baseline этапа зафиксирован в [docs/foundation.md](docs/foundation.md).
